Задача

Разработать минимальную рабочую версию аналитического кабинета для компании «Истинный интеллект».

Система предназначена для клиентов, которые управляют несколькими филиалами и отслеживают показатели присутствия бизнеса на геосервисах.

Ориентировочное время выполнения: 4–6 часов. Допускается использование AI-инструментов. Мы оцениваем не количество написанного вручную кода, а архитектуру, качество реализации и способность объяснить технические решения.

Функциональность

1. Авторизация и роли

Реализовать вход в систему для двух типов пользователей:

* Администратор: видит все компании и филиалы.
* Клиент: видит только данные своей компании.

Необходимо исключить доступ к чужим данным как через интерфейс, так и через прямые API-запросы.

2. Аналитический дашборд

Создать страницу с показателями:

* Количество просмотров карточек.
* Количество переходов на сайт.
* Количество звонков.
* Количество построенных маршрутов.
* Средний рейтинг.
* Количество отзывов.

Добавить фильтрацию по филиалу и периоду, а также график динамики одного из показателей.

3. Работа с филиалами

Реализовать:

* Список филиалов компании.
* Выбор конкретного филиала.
* Просмотр статистики по филиалу.
* Отображение агрегированных данных по всем доступным филиалам.

4. Backend и база данных

Создать REST API и структуру PostgreSQL для хранения:

* Пользователей.
* Компаний.
* Филиалов.
* Ежедневных показателей.
* Отзывов.

Подготовить миграции и тестовые данные минимум для двух компаний, трёх филиалов и двух пользователей с разными правами.

5. Дополнительное задание

Реализовать один из двух вариантов на выбор:

А. Модуль отзывов с возможностью фильтрации по рейтингу и статусу обработки.

Б. Имитацию внешнего API, из которого система получает статистику, сохраняет её в базу и корректно обрабатывает повторные запросы.

Технические требования

Предпочтительный стек:

* React / Next.js / TypeScript.
* Node.js / NestJS.
* PostgreSQL.
* Docker.

Допускается альтернативный стек с обоснованием выбора.

Обязательно:

* Реальные запросы frontend к backend.
* Сохранение данных в базе.
* Серверная проверка прав доступа.
* Обработка ошибок и состояний загрузки.
* README с инструкцией запуска.
* Минимум два автоматизированных теста, один из которых проверяет изоляцию данных разных компаний.

Что предоставить

1. Ссылку на Git-репозиторий.
2. Инструкцию запуска проекта.
3. Скриншоты или короткую демонстрацию.
4. Краткое описание архитектуры.
5. Список известных ограничений.
6. Описание того, как кандидат масштабировал бы решение до 500+ компаний и нескольких тысяч филиалов.

Важно: тестовые данные должны быть вымышленными. Реальные клиентские данные, ключи API и доступы не предоставляются.
